# UniTools 🛠️

**UniTools** — это современный, быстрый и автономный (offline-first) набор инструментов разработчика на каждый день. Все утилиты разделены на изолированные модули, имеют независимые окна ввода/вывода, работают в красивом адаптивном интерфейсе с поддержкой тёмной/светлой темы и мультиязычности.

---

## 🌟 Возможности (Features)

### 1. Форматировщики (Formatters)
* **JSON Formatter** — валидация и форматирование JSON-объектов с мгновенной подсветкой синтаксических ошибок.
* **SQL Formatter (MS SQL)** — строгое форматирование и проверка синтаксиса диалекта **Transact-SQL / MS SQL** с помощью библиотеки `sqlglot`. Показывает точное местоположение ошибок (строку и колонку).
* **XML Formatter** — валидация и форматирование XML-документов, обнаружение несовпадающих тегов и некорректной разметки.

### 2. Кодировщики (Encoders)
* **Base64 Encoder / Decoder** — быстрое кодирование обычного текста в Base64 и обратно в один клик. Поддерживает мгновенную смену направления конвертации (Swap).

### 3. SQL Инструменты (SQL Tools)
* **SQL IN Builder** — преобразует список значений (ID), вставленных построчно, в готовую строку для SQL-запроса `IN ('val1','val2','val3')`. Автоматически экранирует одиночные кавычки/апострофы (например, `O'Brien` -> `'O''Brien'`).

### 4. Утилиты (Utilities)
* **URL Shortener** — сокращатель длинных ссылок с базой данных PostgreSQL и автоматическим 301/302-редиректом на оригинальный URL.

### 5. Системные настройки (Settings)
* **Язык интерфейса:** Русский, Украинский, Английский. Язык автоматически подстраивается под системные настройки вашего браузера при первом запуске.
* **Тема оформления:** Светлая и тёмная темы. Тема плавно переключается и сохраняется в локальном хранилище (`localStorage`).
* **Адаптивный дизайн:** Полностью приспособлен под мобильные телефоны и смартфоны.

## 🛠️ Стек технологий (Tech Stack)

* **Frontend:** React, TypeScript, Vite, Monaco Editor (движок от VS Code), Vanilla CSS (glassmorphism).
* **Backend:** FastAPI (Python 3.11), Uvicorn, Sqlglot (парсинг MS SQL), Sqlparse.
* **База данных:** PostgreSQL 15.
* **Окружение:** Docker & Docker Compose.

## 🚀 Запуск и развертывание (Deployment & Setup)

Для запуска проекта вам понадобятся установленные **Docker** и **Docker Compose**.

### 💻 Разработка (Local Development)

В режиме разработки используются файлы настроек по умолчанию, а изменения в коде фронтенда (`frontend/src`) и бэкенда (`backend/app`) подхватываются автоматически без перезапуска контейнеров (hot reload через volumes).

1. Скопируйте файл переменных окружения:
   ```bash
   cp .env.example .env
   ```
2. Запустите контейнеры:
   ```bash
   docker compose up -d --build
   ```
3. Сервисы будут доступны по адресам:
   * **Фронтенд:** [http://localhost:5173](http://localhost:5173)
   * **Бэкенд API:** [http://localhost:8000](http://localhost:8000)
   * **PostgreSQL:** `localhost:5432`

---

### 🏭 Продакшн (Production - для клиентов)

В продакшн-режиме фронтенд собирается в статические файлы и раздается через встроенный веб-сервер **Nginx** (порт `80`). Nginx автоматически проксирует все запросы к API (`/api/*`) и короткие ссылки сокращателя на бэкенд-контейнер. Это устраняет любые проблемы с CORS, смешанным содержимым (Mixed Content) и избавляет от необходимости открывать дополнительные порты на сервере.

1. Скопируйте `.env.example` в `.env` и настройте переменные:
   ```env
   DB_USER=postgres
   DB_PASSWORD=           # Придумайте надежный пароль
   DB_NAME=unitools
   ```
   > ℹ️ **Примечание:** Переменную `API_URL` для продакшена настраивать **не нужно** — запросы автоматически идут на тот же хост через относительный путь `/api`.

2. Запустите сборку с продакшн-конфигурацией:
   ```bash
   docker compose -f docker-compose.yml -f docker-compose.prod.yml up -d --build
   ```
3. Сервисы будут доступны по адресам:
   * **Веб-интерфейс и API:** [http://YOUR_SERVER_IP](http://YOUR_SERVER_IP) (порт 80)
   * **Сокращенные ссылки:** [http://YOUR_SERVER_IP/{short_code}](http://YOUR_SERVER_IP/{short_code})

## ⚙️ Управление проектом (Operations)

```bash
# Остановить продакшн-сервер
docker compose -f docker-compose.yml -f docker-compose.prod.yml down

# Посмотреть логи всех контейнеров в реальном времени
docker compose logs -f

# Перезапустить определенный сервис (например, backend)
docker compose restart backend
```

## 📦 Что передавать клиентам (Deliverables)

При передаче проекта клиенту для продакшн-развертывания отправляются **только** следующие файлы:
* `docker-compose.yml` (базовая конфигурация)
* `docker-compose.prod.yml` (продакшн-конфигурация)
* `.env.example` (шаблон настроек)
* `README.md` (эта инструкция)
* Исходный код проектов `backend/` и `frontend/` (для сборки Docker-образов на сервере клиента)

> ⚠️ **Важно:** Файл `docker-compose.override.yml` клиентам **не передается** — он предназначен только для локальной разработки.
